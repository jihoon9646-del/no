# OPR 업체 자료 자동 점검

업체가 보낸 자료를 사람이 하나하나 열어보지 않아도, 상품코드 생성에 필요한 정보가 빠진 곳을 찾아 담당자에게 알려주는 스킬이다. 예약 작업으로 1시간마다 아무도 보지 않는 상태에서 돌 수 있으므로, 조용하고 예측 가능하게 동작하는 것이 중요하다.

## 전체 흐름

1. 폴더 찾기 → 2. `scan`으로 새 파일 점검 → 3. 파일마다 결과 메일 발송 → 4. 메일이 나간 파일만 `finalize` → 5. 한 줄 요약

### 1. 폴더 찾기

대상은 OneDrive 안의 `config.json`의 `folder_name` 폴더(기본 `OPR수신자료`)다. 사용자가 경로를 주면 그걸 쓰고, 아니면 연결된(마운트된) 폴더 중 그 이름인 곳을 찾는다. 못 찾으면 추측하지 말고 폴더를 연결해 달라고 요청한 뒤 멈춘다.

점검 대상은 폴더 **바로 아래** 파일뿐이다. `처리완료/`, `열수없음/`은 이미 처리한 파일이라 보지 않는다.

### 2. 새 파일 점검

```bash
python scripts/check_opr.py scan "<OPR수신자료 경로>"
```

스크립트가 처리기록.csv에 없는 새 파일만 골라 JSON으로 돌려준다. 파일별 `status`의 뜻은 이렇다.

| status | 의미 | 할 일 |
|---|---|---|
| `누락있음` | 문제 행이 있음 | 결과 메일 + 업체 요청 초안 |
| `누락없음` | 필수 항목이 모두 채워짐 | 짧은 결과 메일 |
| `열수없음` | DRM, 비밀번호, 손상, 양식 인식 실패 | 이유만 담은 메일 |

엑셀/CSV가 아닌 파일(서명 이미지 등)은 스크립트가 알아서 건너뛴다. 결과가 빈 배열이면 새 파일이 없는 것이다. **메일을 보내지 말고** "새 파일 없음"으로 끝낸다. 1시간마다 돌 때 빈 메일이 쌓이면 담당자가 알림을 무시하게 되기 때문이다.

Python이나 openpyxl이 없으면 `pip install openpyxl`을 시도한다. 그래도 안 되면 같은 규칙으로 직접 판단하되, 판단 근거(어느 열을 어느 항목으로 봤는지)를 메일에 적는다.

### DRM과 암호 파일

`열수없음` 파일은 해제하거나 우회하려고 하지 않는다. 회사 문서보안 체계를 우회하는 일이 되기 때문이다. 스크립트가 준 이유를 그대로 전달하고, 담당자가 원본을 확인하거나 업체에 암호 없는 파일을 요청할 수 있도록 안내하는 것으로 충분하다.

### 3. 결과 메일 보내기

noa Outlook의 `send_email`로 받는 사람 한 명에게만 보낸다. 받는 사람은 `config.json`의 `notify_to`이고, 비어 있으면 noa Outlook의 `get_user_info`로 지금 연결된 사용자 본인의 메일 주소를 찾아 쓴다. 그래야 다른 사람이 설정을 고치지 않고 설치해도 결과가 각자 본인에게 간다. 주소를 확인하지 못하면 메일을 보내지 말고 finalize도 하지 않은 채 이유를 알린다. **업체에게 직접 보내지 않는다.** 초안을 업체에 보낼지는 담당자가 확인하고 결정한다.

파일 하나당 메일 한 통을 보낸다.

**제목**: `[OPR 자동점검] <파일명> - 문제 N건` (누락없음은 `- 누락 없음`, 열수없음은 `- 열 수 없음`)

**본문** (누락있음 기준):

```
파일: <파일명>
점검 결과: 문제 N건 / 전체 M행

① 열 매핑
- 상품코드 ← 'Style No' 열
- 색상 ← 'Color' 열
- (열이 없으면) 사이즈 ← ❌ 열 없음

② 문제 행
| 엑셀 행 | 상품코드 | 빠진 항목 |
| 7 | SP26FW-T001 | 색상 비어있음 |

③ 업체 보완 요청 메일 초안
제목: [보완 요청] <자료명> 누락 정보 확인 부탁드립니다
(인사) 보내주신 자료를 확인하던 중 상품코드 생성에 필요한 정보가 일부 빠져 있어 보완을 요청드립니다.
- 7행 SP26FW-T001 (라운드 티셔츠, L): 색상
...
해당 항목을 채워 회신해 주시면 바로 등록 진행하겠습니다. 감사합니다.
```

초안을 쓸 때 참고할 점:
- `row_preview`의 품목명, 색상 같은 값으로 **업체가 어느 행인지 바로 알아볼 수 있게** 적는다. 행 번호만 있으면 업체가 찾기 어렵다.
- 필수 열 자체가 없으면(`missing_columns`) 행별로 나열하지 말고 "사이즈 열 전체가 없음" 한 줄로 요청한다.
- 문제 행이 30개를 넘으면 메일에는 30개까지만 쓰고 "외 N건"으로 줄인다. 업체에는 전체를 채워 달라고 요청하면 된다.
- 시트가 여러 개면 시트 이름을 함께 적는다.

### 4. 마무리 (메일이 나간 파일만)

```bash
python scripts/check_opr.py finalize "<OPR수신자료 경로>" "<파일명>" <누락있음|누락없음|열수없음> <문제건수>
```

메일 발송이 **성공한 파일만** finalize한다. 메일이 실패했는데 파일을 옮기면 그 파일은 영영 알림 없이 묻히기 때문이다. 실패한 파일은 폴더에 남겨 두면 다음 실행 때 다시 시도된다.

finalize가 파일을 `처리완료/` 또는 `열수없음/`으로 옮기고 처리기록.csv에 남긴다. 이 두 겹 장치 덕분에 같은 파일을 두 번 알리지 않는다. 파일을 직접 옮기거나 기록을 손으로 고치지 말고 스크립트를 쓴다.

### 5. 요약

마지막에 한 줄로 끝낸다. 예: `3건 점검: 누락있음 1, 누락없음 1, 열수없음 1 / 메일 3통 발송`

## 설정 바꾸기

필수 항목이나 업체별 열 이름은 `config.json`에서 고친다.
- `required_fields`: 항목 이름과, 업체들이 쓰는 열 이름 목록. 새 업체 양식에서 열을 못 찾으면 여기에 이름을 추가하면 된다.
- `numeric_fields`: 숫자여야 하는 항목. "TBD"나 빈칸, 0 이하 값을 문제로 잡는다.
- `notify_to`: 결과 메일 받는 사람. 비워 두면 스킬을 실행한 사람 본인에게 간다. 팀 공용 주소 등으로 보내고 싶을 때만 채운다.
- `folder_name`: 점검할 OneDrive 폴더 이름.

스크립트가 열 제목을 못 찾아 `열수없음`(양식 인식 실패)이 나오면, 메일에 파일 위쪽 몇 줄의 내용을 적어 담당자가 어떤 열 이름을 추가하면 되는지 알 수 있게 한다.
